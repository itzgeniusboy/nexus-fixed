# Master Agent implementation progress

The private fork now contains the Master task lifecycle, resumable `run()` entrypoint, checkpoint/resume state, dependency-aware dispatch, explicit blocked-worker semantics, persisted worker evidence, typed capability-aware workers, safe public browser inspection, bounded allowlisted project checks, read-only Git inspection, Termux/PC profile detection, provider/key routing hardening, fast queue acknowledgements, Enter submission fallback, exact image-fixture repair, and compact TUI Master/provider/model indicators. Live `master` prompts now execute a single parent orchestration branch: platform workers use the typed registry, research/coder/reviewer/tester/docs work delegates through the existing TaskTool and Effect context bridge, and one parent result reports step status, changed files, receipts, and discovered build artifacts.

The worker layer deliberately does not run arbitrary shell strings. Web and Android project checks are generated from detected project metadata, parsed against an allowlist, executed with fixed argument arrays, sequentially, with cancellation, 120-second timeouts, and capped output. Failed checks and missing project targets remain blocked rather than successful. Successful checks persist hashed command receipts and bounded workspace-relative artifact paths for APK/AAB and common web outputs. Android `connectedCheck` is skipped unless `adb get-state` confirms a connected device, while Gradle unit/build checks remain available when the project wrapper exists. Git defaults to fixed-argument read-only status inspection, and the GitHub adapter uses only `gh repo view --json nameWithOwner,defaultBranchRef,url`; authentication, push, pull, issue, and pull-request mutations are not performed by these workers. Login, upload, personal data, CAPTCHA/2FA, external submissions, commit/push/PR, and other destructive actions remain approval-gated.

The browser platform now also exposes a secure session state machine and typed Master-worker seam. It can launch a browser adapter, detect sensitive login/OTP/CAPTCHA/approval steps, pause in `awaiting_user`, and resume only after an explicit authenticated-access confirmation; credentials and OTP values are never accepted as worker inputs or persisted. The current implementation remains adapter-based, so a real interactive browser executable/session provider must be supplied on the target PC or Termux environment before full page automation is available.

The legacy SessionPrompt regressions now pin their test sessions to the local `test/test-model`, so they no longer inherit an unrelated external default route. The normal prompt, static local-provider, and shell-to-loop tests pass; a live Master prompt regression confirms coder/reviewer/tester child dispatch and checkpoint completion; Master/worker/capability tests cover receipts, artifact discovery, failed-check blocking, and cancellation. Full workspace typecheck remains constrained by sandbox memory, so focused formatting, lint, and regression suites are the reliable validation path here.
